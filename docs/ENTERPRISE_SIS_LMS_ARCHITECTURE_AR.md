# التصور المعماري الشامل لمنصة مدارس أمين الرضا التعليمية

## الهدف
تحويل النظام الحالي من صفحات إدارية مدرسية إلى منصة تعليمية مؤسسية متكاملة تجمع بين:

- SIS: نظام معلومات الطلاب.
- LMS: منصة تعليم إلكتروني وواجبات واختبارات.
- ERP مدرسي: مالية، حضور، شؤون موظفين، تقارير.
- Analytics: تحليلات أداء وحضور ومخاطر.
- AI Assistant: مساعد ذكي للمعلمين والإدارة.

المبدأ البنيوي الأساسي:

```txt
العام الدراسي → الفصل الدراسي → الصف → الشعبة → المادة → الحصة → المعلم → الطالب
```

وليس الاعتماد على الصف فقط.

---

## 1. الهيكل الأكاديمي الصحيح

### الكيانات الأساسية

```txt
academic_years
academic_terms
grades / classes
sections
subjects
teacher_assignments
weekly_schedule
class_sessions
student_enrollments
```

### العلاقات

- العام الدراسي يحتوي عدة فصول دراسية.
- الفصل الدراسي يحتوي جداول وحصص وتقييمات.
- الصف يحتوي شعباً.
- الشعبة تحتوي طلاباً.
- المادة تُدرّس لشعبة أو أكثر.
- المعلم يُسند إلى مادة + شعبة + فصل دراسي.
- الحصة هي حدث فعلي أو أسبوعي مرتبط بمعلم ومادة وشعبة.

---

## 2. الصلاحيات RBAC + Scope Based Access

الأدوار وحدها لا تكفي. يجب إضافة نطاق الصلاحية.

مثال:

```txt
role = teacher
scope = الصفوف/الشعب/المواد المسندة في teacher_assignments و weekly_schedule
```

### المعلم يرى فقط

- الشعب المسندة إليه.
- المواد التي يدرسها.
- الطلاب الموجودين في هذه الشعب.
- درجاته هو فقط.
- واجباته واختباراته فقط.

### يمنع المعلم من

- رؤية طلاب غير مرتبطين بجدوله.
- رؤية درجات معلمين آخرين.
- تعديل بيانات الطالب الأساسية.
- إدارة المستخدمين والصلاحيات.

## 3. لوحة المعلم المقترحة

### الأقسام

1. ملخص اليوم.
2. حصصي القادمة.
3. حضور سريع.
4. واجباتي.
5. اختباراتي.
6. الطلاب المتعثرون.
7. الطلاب كثيرو الغياب.
8. إحصائيات المادة.
9. ملفات ودروس.

### مؤشرات رئيسية

- عدد الحصص اليوم.
- عدد الطلاب الحاضرين.
- عدد الغائبين.
- واجبات غير مصححة.
- اختبارات قادمة.
- تنبيهات أكاديمية.

## 4. نظام الحضور

### قواعد عامة

- الحضور لليوم الحالي فقط.
- الأيام السابقة لا تعدل إلا بإذن إداري.
- الأيام المستقبلية ممنوعة.
- كل تعديل يسجل في audit log.

### الحالات

```txt
present
absent_excused
absent_unexcused
late
permission
medical_excuse
external_activity
```

### الابتدائي

- حضور الحصة الأولى والثانية فقط.

### المتوسط والإعدادي

- حضور حصة حصة.

### واجهة الحضور

- جدول شبيه Excel.
- كل الطلاب حاضرون افتراضياً.
- يتم تثبيت الغياب/التأخير فقط.
- أزرار جماعية.
- بحث فوري.
- عداد مباشر.
- حفظ تلقائي.


### الأوزان

الابتدائي:

```txt
تقييم مستمر 20%
اختبارات شهرية 80%
```

المتوسط والإعدادي:

```txt

```

الأوزان يجب أن تخزن في قاعدة البيانات ولا تكون ثابتة في الكود.

## 6. نظام الإعفاء

### يطبق فقط على

- المتوسط.
- الإعدادي.

### لا يطبق على

- الابتدائي.

### حالات الإعفاء

```txt
لا يوجد إعفاء
إعفاء مادة
إعفاء عام
مرشح للإعفاء
إعفاء قيد المراجعة
إعفاء ملغى
```

### إعفاء مادة

- متوسط المادة النهائي >= 90.
- حضور مقبول.
- لا مخالفات أكاديمية.
- لا غياب غير مبرر في الاختبارات.

### إعفاء عام

- كل المواد >= 85.
- لا مادة أقل من 85.
- حضور وسلوك مقبولان.
- لا مخالفات أكاديمية.

## 9. التحليلات والتقارير

### للمعلم

- متوسط الصف.
- أعلى وأقل درجة.
- نسبة النجاح.
- المتعثرون.
- الغياب المتكرر.
- تحليل نقاط الضعف.

### للإدارة

- رسوم ومدفوعات.

## 10. الذكاء الاصطناعي

### حالات الاستخدام

- توليد اختبار من درس.
- توليد أسئلة من ملف PDF أو نص.
- اقتراح واجبات.
- تلخيص أداء الطالب.
- اكتشاف الطلاب المعرضين للرسوب.
- اكتشاف الغياب المتكرر.
- توصيات للمعلم والإدارة.

### مبدأ الأمان

- لا يغير بيانات مباشرة.
- يعطي توصيات تحتاج اعتماد بشري.
- يسجل كل طلب AI في audit log.

## 13. الخلاصة

للوصول لمستوى Moodle / Google Classroom / Canvas، يجب نقل التفكير من صفحات منفصلة إلى منصة قائمة على:

```txt
Academic Structure + Role Scope + Learning Activity + Analytics + Audit
```

النظام الحالي أصبح قاعدة جيدة، لكنه يحتاج الآن إلى تثبيت نموذج:

```txt
العام الدراسي → الفصل → الصف → الشعبة → المادة → الحصة → المعلم → الطالب
```

ثم بناء كل الميزات فوق هذا النموذج.
